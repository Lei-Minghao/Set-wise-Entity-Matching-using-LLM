# Set-wise Entity Matching using LLMs – Pipeline Instructions

This repository provides multiple entity resolution pipelines that leverage large language models (LLMs) and vector-based blocking to cluster product/record references from different sources. 

The code supports several benchmark datasets (DBLP-ACM, Walmart-Amazon, WDC, Solute, and custom samples) and includes:

* **Single-prompt baseline** (Gemini) for direct clustering.
* **Improved CoMEM Pipeline**:
  * **Blocking** (TF-IDF / LSH) to generate candidate pairs.
  * **LLM-based ranking** (Qwen) for reordering candidates.
  * **LLM-based selection** (Gemini) to decide which candidates match.
  * **Transitive clustering** (union-find) to produce final entity clusters.
* **Improved LLMCER pipeline** with LSH blocking, MDG separation, and anti-transitivity merging.

All scripts are designed to run on Google Cloud Vertex AI (Gemini) and optionally on local GPUs (Qwen models via Hugging Face).

Install all dependencies with:


## Running Single-Prompt Baseline
`Single_prompt_{dataset}.py` calls Gemini once per dataset to partition all records into clusters.

```bash
cd Single prompt
python Single_prompt_{dataset}.py
```
* **Configuration:** Edit the script to set `DATASET_PATH`, `GROUND_TRUTH_PATH`, and `MATCHING_FIELDS`.
* Results are saved in `Single prompt/results/`.


## Running Improved CoMEM Pipelines

### 1. Blocking (Candidate Generation)
The blocking scripts (inside `CoMEM/`) create candidate pairs for a given dataset using TF-IDF cosine similarity.

```bash
cd CoMEM
python blocking_drop duplicates_{dataset}.py   # replace with your dataset
```
* **Configuration:** Edit the script to set `DATASET_PATH`, `OUTPUT_PATH`, `TOP_K`, etc.
* **Output:** A CSV file (e.g., `sample_walmart_amazon_top25.csv`) stored in `CoMEM/data/`.

### 2. Ranking with Qwen
The ranking scripts (`ranking_qwen_{dataset}.py`) use a local Qwen model to order candidates for each anchor. Two strategies are available:
* **Matching (pointwise):** Each candidate is scored independently.
* **Comparing (pairwise):** Candidates are compared in pairs.

**Example:**
```bash
cd CoMEM
python ranking_qwen_{dataset}.py \
    --model Qwen/Qwen2.5-7B-Instruct \
    --strategy matching \
    --topk 10
```
The script reads the blocked CSV from `CoMEM/data/` and saves a JSON ranking file (e.g., `qwen_rankings_matching_{dataset}.json`) in the same folder.
> **Hardware Note:** For Qwen ranking, ensure you have a GPU with enough VRAM (≥16 GB). The script automatically detects CUDA.

### 3. Selection with Gemini
The selection script (`selecting_{dataset}.py`) uses Gemini to select all matching candidates (over-matching inclusive) from the ranked or unranked candidate list.

```bash
cd CoMEM
python selecting_{dataset}.py
```
It processes the candidate CSV and outputs predictions, classification reports, and confusion matrices.

### 4. Compound Pipeline (Ranking + Selection)
`compound_{dataset}.py` integrates pre-computed Qwen rankings with Gemini selection, then builds transitive clusters.

```bash
cd CoMEM
python compound_{dataset}.py \
    --ranking_file data/qwen_rankings_matching_{dataset}.json \
    --selecting-model gemini-2.5-flash \
    --output results/compound_{dataset}.txt
```
The final output includes per-anchor details and merged clusters.

## Running Improved LLMCER Pipeline
`llmcer_{dataset}.py` implements the full pipeline: LSH blocking, LLM separation with MDG correction, and hierarchical merging with anti-transitivity.

set `run_llmcer.sh`

```bash
export DATASET_PATH="dataset/{dataset}.csv"
export GROUND_TRUTH_PATH="dataset/{dataset_gt}.csv"
export EMBEDDING_MODEL_PATH="all-MiniLM-L6-v2"   # local or HF name
```

execute
```bash
cd LLMCER
./run_llmcer.sh
```
All environment variables (paths, model names) must be set. Output is saved in `LLMCER/results/`.

## Troubleshooting

* **Rate limiting:** The Gemini scripts respect Vertex AI’s default limit of 30 RPM. Adjust `RATE_LIMIT_RPM` if you have a higher quota.
* **GPU memory:** For Qwen-7B, use `torch.bfloat16` (already set). If memory is still an issue, reduce batch size or use a smaller model.
* **Missing lshashpy3:** If installation fails, try `pip install lshashpy3` or install from source. Alternatively, modify `llmcer_WDC.py` to use a different LSH implementation.
* **File paths:** Always check that `project_root = Path("...").resolve()` in each script points to the valid working directory.
